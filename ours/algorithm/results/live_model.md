# Live recogniser: Rules mode vs Model mode

Generated by `algorithm/scripts/export_live_model.py`. Both modes: kind (nod / tilt / turn / circle / none), then direction from one sign. Model = logistic regression on `share_x`, `share_y`, `share_z`, `linearity`, `abs_loop_xy`, `abs_loop_xz`, `abs_loop_yz`. Rules: dominant axis share >= 0.6 -> nod/tilt/turn, else |loop| >= 0.15 -> circle, else none.

Training data: 6439 EarSet events (30 people), 28 P01 app-session motions, 32 P01 earlier-recording motions, 12 P01 talking events.

## EarSet, leave one person out (each person tested by a model trained on the other 29 + P01)

- **Rules**: kind accuracy 0.41; head gestures right 0.94; no-gesture events called 'none' 0.17
- **Model**: kind accuracy 0.73; head gestures right 0.96; no-gesture events called 'none' 0.62

Rules have no real 'none' test (anything with one dominant axis is a motion): in the app the pair rule and the detector carry most of the false-command protection, as before.
