CS724 · Group 6 · Gesture Collector v2.1

How much data the experiment collects

20 participants, each recorded on AirPods Pro 2 and AirPods 5, about 50 minutes per device. Every number below comes from the app's own session planner and from the size of the first real session (P01).

At a glance

"Motion examples" counts single-motion trials plus the motions inside commands. 8 candidate motions: nod down, look up, tilt left, tilt right, turn left, turn right, circle clockwise, circle counter-clockwise.

What a participant's two sessions look like

The time budget is set to 50 minutes. The core runs first on each device and is never cut. Optional modules follow in the participant's own order (rotated by participant number) and run only if they fit whole. Leftover time becomes extra sitting rounds. Example: P01, whose module order is A, B, F, C, E, D.

One trial, to scale (about 9.3 s)

name spoken
GO beep → 4 s window
random gap 2.5–5 s

The announce time and the GO time are both logged. The labeller opens the motion window at the announcement, because people start moving as soon as they hear the name. After each window the app shows a one-motion check ("✓ one motion", "do it ONCE", "no motion seen"). A round is 8 motions + 2 idle cues in random order.

Limits to plan around

  • Only one earbud streams at a time. If it comes out, the stream moves to the other one and the app recalibrates.
  • Motion data reportedly stops while the AirPods microphone is in use, so no calls during a session.
  • The vocabulary (8 candidates, 20 placeholder commands) is decided after the 5-person pilot, by editing plan.json; the app needs no rebuild.
  • Numbers assume the app's default timing: 4 s window, 2.5–5 s gap, 1.3 s spoken cue, 10 cues per round.
