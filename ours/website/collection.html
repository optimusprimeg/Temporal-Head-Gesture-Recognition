Data collection

One Mac, one pair of AirPods, one continuous session

The Gesture Collector app (macOS) runs the whole session: it explains each motion with a 3D head, speaks the cues through the AirPods, records every sample, checks each trial live, and resumes after a crash. It replaces the earlier set-up (Sensor Logger on a phone plus a separate cue script), which cut the data into 2.5-second clips and had no real no-gesture time.

What happens in one session

  1. Participant and time. First name, number (P01, P02...), and how many minutes they have. Names are kept in the data, as the team decided.
  2. Device check. Sample rate (50 Hz, 25 on some models), gravity close to 9.81 m/s², which earbud is streaming, and the AirPods model macOS reports. A live 3D head follows the person's head.
  3. Calibration. 4 s still (sets the person's still level), 3 slow nods with the chin going down first (sets the head frame), then look left, right and front. Repeated after re-wearing, and automatically if the stream jumps to the other earbud.
  4. Practice. 2 trials of each motion in the first session (1 later), with the 3D head showing the motion and the person's own head side by side.
  5. Core blocks, then optional modules, in the order the time-budget planner chose (below).
  6. Export. One folder per session, zipped, ready to hand over.

One trial (cue)

The motion is shown on screen and spoken through the AirPods (for example "tilt left"). The app logs that moment, then plays a GO beep, reserves 4 s for the motion (6 s for a command), checks it live ("one motion ✓", "we saw 3 motions: do it ONCE", "no motion seen"), and waits a random 2.5 to 5 s so the rhythm is not predictable. Two "nothing" cues per round record stillness on purpose.

Fitting any amount of time, fairly

Time budget

The experimenter types the minutes available (15 to 120). The planner puts the core first, then as many optional modules as fit, then extra rounds. Short on time? You still get the core.

Rotated module order

Modules A-F follow a Williams Latin square by participant number, so every module is early for some people and late for others (fatigue and practice even out), and each module follows each other one equally often. Re-wear is never last.

Device crossover

Half the people start with AirPods Pro 2, half with AirPods 5; the second session uses the other model. Device and session order are therefore not mixed up.

Planned missing data

Not everyone does every module; the rotation spreads them evenly, and the roster tracks what each person has done on each device so the next session fills the gaps.

What the check confirmed as correct: the Latin square is the standard design, the core repeats on each device (a proper crossover), the live one-motion check only gives feedback and never forces a retake (so no trial is selected by the classifier), and resume and repeat-after-earbud-switch work as intended.

From recording to labels

Nothing in the data assumes how long a motion lasts. The detector (the same one used live) finds events in the continuous stream, and the cue log names them:

  • A motion window opens 0.3 s before the motion is announced (people start early: 61 % of P01's motions began before the GO beep) and closes 4 s after GO.
  • If several events fall in one window, the largest is the motion and the small ones are marked "extra".
  • Events in a "nothing" cue or a no-gesture block are "none" (not a gesture).
  • Practice, calibration, re-wear steps, and cues the experimenter marked skipped or disturbed are excluded.

Files per session: stream_NNN.csv (every sample), cues.csv (every cue with its announce and GO times and the live verdict), notes.csv (experimenter actions, earbud switches, data gaps), session.json (who, which device, versions) and state.json (for resume).
