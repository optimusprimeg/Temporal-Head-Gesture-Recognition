The command idea

A command is two head motions in a row

We train the system on only 8 simple head motions. A command is an ordered pair of two different motions, the second starting within 1.5 seconds after the first ends. "Tilt left, then nod down" means GO FORWARD.

The 8 single motions

Each motion is one smooth go-and-return: out, and straight back to the front, without holding.

They come in four families, one per way the head can move: nod (about the ear-to-ear axis), tilt (about the nose axis), turn (about the vertical axis) and circle (all three, in a loop). Inside a family, the two motions differ only in direction, which the recogniser reads from the sign of the first swing (or the loop direction for circles).

Why two motions instead of one

Everyday motion is not a command

People nod while listening and turn to look around. A single motion is never enough: it is dropped after 1.5 s if no second one follows, so one stray movement cannot send a command. Two motions in a valid order within 1.5 s are much rarer by accident.

Many commands from few parts

8 motions give 8 × 7 = 56 ordered pairs. Adding a command means editing a list, not collecting new training data. A single-gesture design (the earlier version of this project) needs new data and retraining for each new command.

Learnable and private

Each part is a natural motion that looks ordinary to an observer. The dictionary (which pair means what) is private to the team, like a call sign, and can change without retraining.

How a command is recognised

  1. The detector finds a motion. It watches how much the head rotates compared with the person's own still level. A motion starts when rotation stays above 4 × that level for 0.06 s and ends after 0.4 s back near stillness. Motions can last 0.3 to 4 s: nothing assumes a fixed length.
  2. The motion is named. Which axis carried most of the rotation gives the family; the sign of the first swing gives the direction (details on Features).
  3. The gate. In Model mode, a motion counts only if the model is at least 50 % sure and clearly prefers it over the runner-up; "not a gesture" is one of the model's answers.
  4. The pair decoder. The first accepted motion waits. If a second one starts within 1.5 s of its end and the pair is in the dictionary, the command is sent. Otherwise the first is dropped (and the second may start a new command). The same motion twice is never a command, because nod-nod is what people do when they agree.

All 20 commands, built from P01's real recorded motions joined with a pause of the given length (3 versions each). The commands that still fail with a pause all contain a circle.

Why the pause: the detector ends a motion only after 0.4 s of near-stillness. Two motions done back to back without that stillness merge into one long event and the command is lost. On real fast doubles from 4 earlier participants (tilt-tilt, nod-nod), 84-89 % merged. The instruction for now is therefore: first motion, back to the front, a short still pause, then the second motion.

Making the pause optional: cut where the axis changes

In a cross pair such as tilt-then-nod, the axis carrying the rotation switches half-way: first tilt, then nod. A merged event can be cut at that switch. A double tilt has no switch, so it cannot be rescued that way, which is another reason the dictionary avoids same-motion and same-family pairs where possible.

The real recordings behind this picture were shown in the project discussion (P01's motions; an earlier participant's double tilt). The cut rule is designed but not yet built or tested.

The pairs that stay hard

Pairs inside one family (tilt left → tilt right = HOLD POSITION / MOVE; look up → nod down = ACK) stay on one axis; only the direction flips. Those need the pause, or they are replaced when the final 20 are chosen.

Open questions about commands

  • Real recorded cross pairs do not exist yet: the pilot's command blocks and a self-test with the live recogniser provide them.
  • Command accuracy on new people (the pilot measures it on 5 people, then 20).
  • How often everyday movement produces each pair, which decides the final 20.
  • Circles: the weakest motion so far. If the pilot confirms it, the 6 one-axis motions still give 30 pairs.
